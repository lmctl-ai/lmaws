# Ownership, profiles, teardown and cost

`Sandbox` accepts only fresh run-owned names: `lmaws_<run-id>_...`, or
`lmaws-<run-id>-...` for S3, with `lmaws_test=<run-id>` ownership tags. It forces
creation intents to a new JSONL ledger before requests; updates/deletes require
a run entry and provider-verified tags. Cleanup runs in reverse order on success,
exceptions and shutdown. Failed cleanup remains recoverable, not falsely deleted.
Sweeping (`lmaws --sweep DIR --older-than-hours 0` or `Cloud.sweep`) is local,
dry-run only; it never authorizes deletion of discovered account resources.

Real resource mutations require `LMAWS_LIVE=1` and active profile `lmaws` (service
sandboxes) or `lmaws-ec2` (EC2 spot nano sandbox) in `us-east-1`. The IAM grant interface and scoped credential helper have separate guards; agents
never use admin:
1. Customer-managed `lmaws_` IAM policy mutation (`iam_policy_put` and
   `iam_policy_delete`), which requires `AWS_PROFILE=admin`, `LMAWS_ADMIN_GRANT=1`,
   `--apply` (`LMAWS_APPLY=1`), `LMAWS_LIVE=1`, and a policy name matching
   `^lmaws_[a-z0-9_-]{1,64}$`. `lmaws`/`lmaws-ec2` are refused for IAM policy writes.
2. Federated session credential issuance (`lmaws --credential-process <mode>` for
   `default`, `lmaws`, `lmaws-ec2`, `lmaws-web`) reads ONLY static credentials from the
   explicitly selected source profile (`--source-profile` or
   `LMAWS_CREDENTIAL_SOURCE_PROFILE`; default `agent-issuer`) in shared
   credentials/config files. A source profile whose name contains `admin` is refused unless
   the human-only `LMAWS_ALLOW_ADMIN_SOURCE=1` override is explicitly set. Ambient environment,
   SSO, web identity, container and EC2 metadata sources are never used. `default` loads the
   policy file from `--policy-file`, `LMAWS_DEFAULT_SESSION_POLICY`, or
   `~/.aws/session-tools/tasks/iam-snapshots/local-default-session.json`, compacts it and sends
   it with `ReadOnlyAccess`; the combined compact policy and ARN must fit STS's 2,048-character
   limit. The three `lmaws*` modes resolve the source account with STS and send the account-scoped
   `lmaws_session` managed-policy ARN. All modes use `awsspot-local-<mode>`, 3,600 seconds, and owner-only cache files until 5 minutes before expiry. Cache scope includes the
   source profile and policy inputs; no resources or permissions are changed.
Inline STS session policies are capped at 2,048 characters, whereas customer-managed
IAM policies allow up to 6,144 compact characters. Before any `iam_policy_put`,
`IamPolicies.lint` verifies valid JSON, compact length `<= 6144`,
`"Version": "2012-10-17"`, and that every `Allow` statement is either read/inventory
or scoped by `lmaws-*`/`lmaws_*` resource name, `lmaws_test` tag, or condition,
while refusing `iam:*`, `sts:AssumeRole*`, `organizations:*`, `account:*`, `kms:*`,
`secretsmanager:*`, bare `'*'`, or `'Resource': '*'` with a write action. The
managed policy `lmaws_session` (5,290 compact characters, 23 statements) is
generated byte-for-byte by `recipes/session_policy.lms` (using `example.com` in
committed code and `--domain` for real runs), applied live via
`recipes/grant_session_policy.lms`, and verified with `0` diff against the live
default policy version. Live IAM policy simulator calls (`policy_simulate` and
`policy_simulate_principal`) also require `AWS_PROFILE=admin`. Never copy real
policy contents, account IDs or credentials into repository files.

`CostLedger` embeds its us-east-1 price snapshot in each ledger with decimal unit
prices, resource lifetimes in minutes, SDK transmission attempts/retries, billing
units and storage upper bounds. Prices are estimates, vary by region/time and
ignore free-tier credits; the original owned-test flows make no billing calls. The new Spend API explicitly meters paid CE pages and metric requests under its own <=$0.25 cap. SQS/SNS
payload accounting uses 64 KiB units; DynamoDB writes round to 1 KiB; storage uses
a 30-day month. Cleanup headroom is reserved before another creation/request;
cleanup remains allowed after cap exhaustion.

`LMAWS_MAX_COST_USD` defaults to $0.05 per program/example, with a hard $0.25
ceiling. Sessions share one cost ledger; separate independent autoruns do not
share a cumulative cap. Use the live/comparison campaign harness for a capped
batch. `aws.example` emits sanitized evidence with leftovers, verification and
prices; read-only output is `estimated cost: $0.00`, writes retain fractional
estimates (including denied attempts). Private raw ledgers retain exact resource
IDs for recovery; public output masks account IDs and never includes credentials,
secret values, payload contents or raw SDK errors. See [live results](03-live.md).

Read-only Spend reports are an explicit paid-query exception: Cost Explorer
$0.01/page and CloudWatch metrics are admitted before dispatch, including failed
attempts. Billing estimates are not hidden as $0.00 merely because no resource
was created. See [spend safety](09-spend-reports.md).
