# Recipes and synthetic examples

`recipes/README.md` and the marked README recipes section are generated by
`scripts/recipe-index.py --write --root-readme README.md` from the executable
recipe headers. Each row states file, purpose, AWS access, arguments and typical
cost. `scripts/generate-recipes.py` owns thin entry wrappers and their examples.

Import paired `recipes/lib/*.lms` files from local paths or raw HTTP(S) URLs.
Libraries only declare functions; executable wrappers call them with parsed
arguments. Imports do not query AWS, change environment settings or create files.
Executable entries and picture examples inline their shared source through the
generator. This avoids the current top-level URL runner resolving a relative
import against the empty working directory. Keep URL-import composition in the
paired libraries; test empty-directory caption commands before changing this.

Shared options cover period, top-N, prefix, region/profile, output, cap, preview
and apply. Examples force synthetic mode even if live mode was inherited. A script
reserves each live call's full cap against a shared $0.25 ceiling. Inventory and
sandboxes default to $0.05; spend defaults to $0.25 unless the caller supplies a
cap or LMAWS_MAX_COST_USD. Native ledgers still report actual modeled requests.

Live inventory needs `--live`; owned sandbox writes additionally require
`--apply --profile lmaws`. Ledger/tag/teardown behavior stays in the native host.
The prefix search covers the 14 supported non-IAM metadata APIs in the selected
region plus their global inventories, not every AWS service or region. Prefix
matches are never deletion authority. Leftover reports read selected local run
ledgers; the current sweeper remains read-only. Unknown tag metadata is not
reported as compliant, and stopped state alone does not establish idle duration.

`test.sh` checks index/header/image contracts and actual import/composition/
preview/profile behavior without cloud credentials. The native gallery stage
runs every recipe example. There are 38 recipe/example pairs across all seven requested task groups,
including the account spend detail and seven per-topic spend reports. The spend
functions use the concurrent Spend API; their hosted commands require its
spend-capable native release. Preview works without querying AWS.
