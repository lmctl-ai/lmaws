# Guarded web-stack integration

`Cloud.web_stack(run_id, domain, private_state_path)` opens a persistent `Web` handle. `step(operation, JSON)`, `status()`, `leftovers()`, and `down()` support the lmscript integration in lmweblab. Raw provider IDs stay in private state. Live mutations require `AWS_PROFILE=lmaws`, `LMAWS_LIVE=1`, us-east-1, the run namespace and exact ownership tags. State lives under `.lmweblab-local/`, uses a process lock and atomic writes, and must not be published.

Steps cover private S3/BPA/uploads, CloudFront OAC and tagged distributions, ACM DNS validation, scoped Route 53 alias/A/CNAME changes and bounded waits, and a public spot nano with caller `/32` HTTP ingress. The instance, disk, ENI and spot request are tagged; the server schedules shutdown with instance-initiated termination. Cleanup checks live ownership and performs a fresh inventory before declaring zero.

AWS requires a certificate covering every custom CloudFront alias, even for HTTP. Obtain and validate ACM before testing the alias with `allow-all`; the HTTPS phase changes the viewer policy to redirect. Distribution creation without an alias can precede ACM.

Local safety gates: `WebStackChecks`, `WebTransportChecks` and `scripts/test-web-http.py`. HTTP assertions in lmweblab use lmcurl; committed pictures contain synthetic fixtures. No live completion is claimed by these fake checks.

The local native gate also runs `scripts/test-web-native.py --host target/lmaws`: real native SDK calls go only to localhost fixtures, including foreign-tag and zero-cap refusal. The Linux linkage check permits only system glibc; the measured local native binary is approximately 94 MiB. JVM proxy request tests remain outside the native built-in self-test.

Certificate preparation may precede distribution creation; the distribution then receives the issued certificate and HTTP alias at creation, avoiding a second deployment wait. Spot creation retries only explicit capacity errors (at most twelve attempts/180 seconds) across public subnets in the same VPC and the two permitted nano architectures. Standard CPU-credit mode prevents surplus-credit charges. OAC deletion additionally requires the private creation nonce recorded in state, because OAC does not support run tags. DNS creation proofs are persisted before INSYNC polling.

`Cloud.web_find(run_id, domain)` reads provider state without the lifecycle file lock, so status works during deployment. HTTP suites reserve a bounded request/transfer estimate before dispatch, then record response counts and payload bounds; interrupted suites retain the admitted upper bound. Each cost ledger includes a `cost_web_snapshot` with the whole-run estimate and web price table.

The lmweblab Part A live campaign passed both HTTP and HTTPS. A separate native host process checked all seven attempt namespaces and found zero active leftovers. The successful stack estimate was $0.00107766, including an independent redirect probe; the complete campaign estimate was $0.00513459. Numeric evidence and phase timings are maintained in [lmweblab](https://github.com/lmctl-ai/lmweblab/blob/main/evidence/lmaws-summary.json). No live identifiers are copied into this repository. The immutable patch containing the unavailable-AZ retry is v0.1.16; earlier tags remain unchanged.


Scenario engine details live in lmweblab `scenarios/`. `dns_app` can discover its zone independently of certificates. `dns_weighted` creates an exact run-scoped weighted alias/A pair, then shifts weights repeatedly; initial records must be absent, later targets must match the recorded CloudFront domain and instance IP. All exact-name records are discovered and foreign records block teardown. DNS callbacks persist accepted changes before bounded INSYNC waits.

`lambda_distribution` supports a Lambda URL origin (03) or S3 default plus `/api/*` Lambda origin (05); API TTLs are zero. The function name, provider run tag and NONE-auth URL must match before adoption. The mixed mode creates its OAC and bucket policy. The Lambda-only and mixed S3/API origin paths passed live propagation and HTTP tests in lmweblab scenarios 03 and 05.

`Cloud.serverless_stack(run, domain, path) -> Serverless` persists table/bucket/Lambda/event receipts across host exits. `step("table"|"bucket"|"lambda"|"event", JSON) -> Row`, `status() -> Row`, `leftovers() -> Rows`, and `down() -> Row` are separate from auto-closing `Run` sandboxes. State is locked, atomic, private and checked for run/domain/mode mismatch. Live mode requires profile lmaws, explicit live enablement and us-east-1; demo/loopback fixtures remain available. Custom log groups are created/tagged before Lambda creation and supplied through LoggingConfig.

Lambda code is ZIP-packaged from the supplied source file and receives the owned table/bucket/run/TTL settings. The role argument is exactly `lmaws_lambda_exec` (short name, resolved in the caller's account); Python 3.11/3.12, memory 128–512 MiB, timeout 1–30 seconds. Public URLs require an explicit reason and both URL-only invoke permissions. Event schedules are bounded minute rates; targets require the same run tag and scoped Lambda permission. Existing EventBridge rules and bucket notifications are refused. DynamoDB TTL/item calls check provider ownership. Source APIs offer explicit run-id overloads so receipt IDs are not confused with scenario IDs.

The default `test.sh` runs `scripts/test-lambda-event-transport.py`: actual SDK HTTP serialization, ZIP content, permissions, tags, TTL/items, notification preservation, foreign-resource refusal, and durable reopen/failure cleanup. These checks use synthetic credentials and a fresh loopback port. Admin is rejected by normal recipe entry points and generated examples; only the explicit session-policy and Lambda-role grant recipes enable their parser, while the existing SDK IAM grant guards still apply.


The current live Lambda campaign is [lmweblab structured evidence](https://github.com/lmctl-ai/lmweblab/blob/main/scenarios/lmaws-lambda-results.json): scenarios 03–06 passed HTTP contracts and actual scheduled production; five attempt namespaces were empty after final settlement. No IAM, role or credential-file edits were made. The native ledger uses admitted HTTP/Lambda/log bounds and SDK journals, not AWS invoice reads.

AWS documents 5–10 minute log-delivery latency. An immediate group deletion can be followed by an untagged runtime recreation, observed live. `Serverless.settle(max_seconds)` (1..900) waits through the ten-minute delivery window, reruns owned cleanup and verifies provider inventory. A late empty-tag primary log group may be repaired only with matching private creation receipts, exact run/function/name, an absent function and provider creation time inside the run/deletion+15-minute window. Foreign tags, pre-existing groups and mismatched receipts fail closed. Decisions/errors stay private. [AWS guidance](https://docs.aws.amazon.com/lambda/latest/dg/monitoring-cloudwatchlogs.html).

Source gates cover real SDK serialization, receipt/cap/adversarial cases, idempotence and VM failure cleanup. Current verification is Linux/JVM plus lmcurl and loopback transports; do not reuse an older native release's proof for the new settlement method. PolicyBuilder's session template now retains v6's exact Lambda-only PassRole statement, with 23-statement parity. No policy is applied by these checks.
